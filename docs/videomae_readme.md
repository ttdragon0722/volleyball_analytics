# VideoMAE 比賽狀態標註規範

本文件規定 **SERVICE / PLAY / NO-PLAY** 三種比賽狀態怎麼標，供 VideoMAE 比賽狀態模型訓練使用。
標註工具是網頁版的 `videomae_labeler`（操作說明見 `src/videomae_labeler/README.md`）。
規則和 `docs/tutorial_videomae.md` 第 3 節一致，本文件補上更細的邊界與特殊情況。

> **最重要的一條：同一個情況永遠用同一種標法。**
> 模型學的是你的標註。邊界前後差個幾幀影響不大，但同一種情況這次標 play、下次標 no-play，模型就學不會。

## 0. 開啟標註工具

### 啟動

開一個 PowerShell 視窗，執行：

```powershell
cd D:\coding\volleyball_analytics\src
..\.venv\Scripts\python.exe -m videomae_labeler
```

- 幾秒後瀏覽器會自動打開 **http://127.0.0.1:8765**。沒有自動打開的話，自己在瀏覽器輸入這個網址。
- 終端機出現 `VideoMAE Labeler → http://127.0.0.1:8765` 就代表啟動成功。**標註期間不要關掉這個 PowerShell 視窗**，關掉工具就停了。
- 一定要先 `cd` 到 **`src`** 資料夾再執行，不然會出現 `No module named 'videomae_labeler'`。
- 提示字元前面出現 `(base)` 或 `(volleyball-analytics)` 都沒關係，因為指令裡直接指定了專案自己的 Python。

### 關閉

1. 先在網頁上按 **`Ctrl+S`**，確認右上角顯示「已儲存」。
2. 回到 PowerShell 視窗按 **`Ctrl+C`**。

### 開始標註

1. 按「**開啟影片**」，會跳出 Windows 的選擇檔案視窗（預設從 `D:/user/Downloads` 開始）。
   要繼續標之前的影片，也可以按「**已標註的影片**」直接從清單選。
2. 新影片先在右上角的下拉選單**選好模型**（預設是最新訓練出來的模型），再按「**模型預標**」。
3. 播放影片，**按住** `1` Service／`2` Play／`3` No-play 修正模型的錯誤（規則見下面第 1～3 節）。
4. 隨時按 **`Ctrl+S`** 存檔。沒有按 Ctrl+S 之前，資料庫裡不會有任何變更。

### 常見問題

| 狀況 | 解決方法 |
|---|---|
| 網頁打不開 | 確認 PowerShell 視窗還開著，而且沒有出現錯誤訊息 |
| 更新程式後畫面怪怪的，或出現奇怪的錯誤 | 重啟工具（`Ctrl+C` 後再執行一次），然後在網頁上按 **`Ctrl+Shift+R`** 強制重新整理 |
| `[Errno 10048]` 或 port 被佔用 | 工具已經開著了（可能在另一個視窗），直接用瀏覽器打開網址就好 |
| 影片打開後一直顯示「正在轉成相容格式」 | 這是瀏覽器無法播放的編碼，正在轉檔，只需要轉一次。等進度跑完就好 |
| 「模型預標」按鈕不能按 | 下拉選單是空的，代表找不到模型。確認 `src/weights/game_state` 或 `output/game_state_models/` 裡有模型 |

### 訓練新模型

標好新影片後，可以用 `game_state_trainer` 訓練新模型。指令要在**專案根目錄**執行，不是 `src`：

```powershell
cd D:\coding\volleyball_analytics
$env:PYTHONPATH = "src"
.venv\Scripts\python.exe -m game_state_trainer --list
.venv\Scripts\python.exe -m game_state_trainer `
    --train "訓練影片1.mp4" "訓練影片2.mp4" `
    --val   "驗證影片.mp4" `
    --out   output\game_state_models\v3
```

訓練完成後，在標註工具的網頁按重新整理（不用重啟工具），新模型就會出現在下拉選單裡，並且變成預設。詳細說明見 `src/game_state_trainer/README.md`。

## 1. 三種狀態的定義

| 狀態 | 意義 | 開始 | 結束 |
|---|---|---|---|
| **service** | 發球動作 | **擊球前約 1 秒**：發球員站在端線後、開始發球動作 | 球**越過球網**的那一幀（或球在越網前死掉的那一幀） |
| **play** | 球在比賽中（live ball） | service 結束的下一幀 | 球**死掉**的那一幀：落地、出界、被抓住，或明顯犯規停止 |
| **no-play** | 其他所有時間 | 球死掉的下一幀 | 下一個 service 開始的前一幀 |

一個正常的回合在時間軸上會是：

```
… no-play │ service │ play ………………………… │ no-play …
          ↑擊球前約1秒 ↑球越網              ↑球落地
```

一段 service 通常是 **1.2～3 秒**（擊球前 1 秒，加上球飛到網子的時間）。

> 為什麼從「擊球前約 1 秒」開始，而不是從拋球開始：拋球很短，又常被網子、球員或裁判擋住；
> 而且模型每次看 1 秒的畫面，太短的 service 幾乎不會有完整落在裡面的窗口。
> 用擊球時間往前推 1 秒，就算拋球被擋住也標得出來，標法也比較一致。

### 判斷「球死掉」的時間點

- 以**畫面上看到的事件**為準（球碰地、出界、被抓住），**不是**裁判吹哨的時間。哨聲通常晚 0.5～1 秒。
- 看不到球落地時（被球員擋住、鏡頭沒拍到），就以球員明顯停止動作、開始走動或慶祝的那一刻為準。
- 球落地後滾動、彈跳、球員去撿球，全部是 **no-play**。

## 2. 特殊情況

### 發球相關

| 情況 | 標法 |
|---|---|
| 一般站發、跳發、跳飄 | 一律從**擊球前約 1 秒**開始算 service，所以拋球、跳發的助跑都會包含在裡面。更早之前的拍球、走位、深呼吸都是 no-play |
| 拋球或擊球被擋住 | 用看得到的線索推算擊球時間（球從遮擋處飛出、發球員的揮臂），往前推約 1 秒開始標 service。**不要因為被擋住就不標**，不然那個發球會變成 no-play，模型會學到「發球 = no-play」 |
| 整個發球都看不到（發球員不在畫面內） | 越網前照樣是 no-play，從看到球在空中開始標 play |
| 發球直接得分（ace） | service → 球越網後很短的 **play** → 球落地後 no-play。即使 play 只有不到 1 秒也要標 |
| 發球掛網、沒過網 | service 一直到球掛網落下（或明顯不會過網）的那一幀，接著直接 no-play，**中間沒有 play** |
| 發球擦網後過網 | 算正常發球，service 到球越網為止，之後是 play |
| 發球出界 | 跟 ace 一樣：service → 短暫 play → 球落地後 no-play |
| 拋球後沒有擊球（接住球、重新發球） | 整段標 **no-play**。沒有真正發出去的球不算 service；之後真正發球時，再從那次擊球前約 1 秒開始標 |
| 發球員踩線、裁判立刻吹停 | service 到球員停止動作或球被接住為止，之後 no-play |

### 回合進行中

| 情況 | 標法 |
|---|---|
| 救球後球飛到場外，又被救回來 | 只要球還沒死，就持續 **play** |
| 攔網出界、打手出界 | 球落地或出界的那一幀結束 play |
| 持球、連擊、觸網等犯規，裁判吹停 | 以球員停止動作的那一刻結束 play（通常就是吹哨的時候，這是唯一以哨聲為準的情況） |
| 回合中鏡頭短暫被擋住（1 秒以內） | 照實際狀態繼續標 play |
| 回合中鏡頭長時間看不到球場（轉播切到觀眾或教練） | 看不到的部分標 **no-play**。模型只看得到畫面，不要它從觀眾鏡頭猜出 play |

### 非比賽時間（全部是 no-play）

- 撿球、傳球給發球員、走回位置、輪轉
- 慶祝、擊掌、教練指導
- 暫停、換人、局間休息、技術暫停
- 挑戰（challenge）、看重播判決的等待時間
- 轉播的**重播與慢動作**、記分板／廣告等全螢幕圖卡
- 場邊熱身、場外有人在練球（以主場地的比賽為準）

### 熱身與練習

- 沒有計分、但動作和比賽一樣（有發球、有完整回合）：**照比賽的規則標**。
- 零散的扣球練習、對傳暖身：標 **no-play**。這些不是我們要模型找出來的比賽。

### 判斷不了的時候

- 看不清楚的片段寧可標 **no-play**，或者整部影片都不要用。**不要亂猜**。
- 同一種疑難情況第一次出現時，決定好標法，然後補記在本文件的「團隊補充約定」（第 6 節），之後都照這個標法。

## 3. 用標註工具標註的流程

新影片先按右上角的「**模型預標**」，時間軸就會變成**模型的預測**：模型判成 play / service 的地方保留，其餘全部是 no-play（淡色、「預設」）。已經存過的影片打開時，會直接載入上次存的結果。
你的工作是把它**修正成正確答案**。

1. **從頭到尾看一遍**。建議用 1× 速度；遇到發球就按 `[` 降到 0.5×。
2. 用**按住**的方式修正：
   - 漏掉的發球 → 擊球前約 1 秒**按住 `1`**，球越網時放開
   - 漏掉的回合 → 球越網時**按住 `2`**，球死掉時放開
   - 模型多判的 play / service（例如撿球被判成 play） → **按住 `3`** 把它蓋成 no-play
   - 你按住標的範圍一律**蓋過模型**。
3. **邊界不夠準**的話：暫停 → 點選片段 → 用 `,` `.` 逐幀移到正確位置 → 在右側按「⌖ 目前」設成起點或終點 → 套用。也可以直接拖曳片段邊緣。
4. 用 `A` `D`（或 `←` `→`）倒退或快轉 3 秒，回頭確認。
5. **`Ctrl+S` 儲存**。沒有按 Ctrl+S 之前，資料庫裡不會有任何變更；關閉網頁前工具會提醒你。

### 反應時間

按鍵一定會比畫面慢 0.2～0.3 秒。有兩種做法：

- **提早按**：看到發球員在端線後準備發球，就先按住 `1`。
- **先暫停再開始**：找到擊球的那一幀，按 `A` 倒退 3 秒，再按 `D` 快轉（或用 `,` `.` 逐幀）停在擊球前約 1 秒，按住 `1` 之後再按 `Space` 播放。按住期間只要影片在播，就會一直標。

service 只有 1～2 秒，是最需要精準的類別，建議用第二種做法或 0.5× 速度。

## 4. 資料怎麼被用來訓練（為什麼這些規則重要）

- 匯出時，**每一段 service 會變成一個訓練片段**（整段取樣成 16 幀）。漏標一個發球，就少一筆最稀少的資料；service 段如果拉得太長、混進 play，模型就會分不清楚兩者。
- play 和 no-play 是從片段裡**隨機取 16 幀的窗口**。標錯的區段會被隨機抽到，直接變成錯誤的訓練資料。
- 推論時，模型每次看 **1 秒的畫面**判斷狀態。所以不到 0.3 秒的零碎片段幾乎沒有意義，通常只是手滑，看到了就修掉。
- **存檔時會把整部影片都存下來**，包含你沒有修正過的模型預測與預設 no-play，匯出時全部會被當成正確答案。
  因此：**一部影片沒有從頭到尾檢查完，就不要拿去匯出訓練**。中途可以先 Ctrl+S 存進度，但要記得還沒檢查完。

資料庫裡的記錄方式（和原本的 vb_annotator 相同）：

| 時間軸上顯示 | `source` | `confidence` |
|---|---|---|
| 你按住標註或手動修改的 | `manual` | 1.0 |
| 模型預測的 play / service | `model` | 模型的平均信心 |
| 預設 no-play（兩者都沒有的地方） | `model` | 0.0 |

存檔時，**相鄰且狀態相同的片段會合併成一段**（例如模型的 service 中間被你按住 `1` 修正過，存檔後仍然是一整段 service），
所以匯出時一次發球只會變成一個訓練片段。合併後只要有任何一部分是手動標的，`source` 就記為 `manual`；
`confidence` 是各段依長度加權的平均。

## 5. 每部影片標完的自我檢查

- [ ] 整部影片從頭看完了，沒有跳過的段落
- [ ] **每一個 play 前面都有 service**（除了發球掛網、沒過網的情況）
- [ ] 回合數和比分大致吻合（例如 25:20 加上幾個發球失誤，大約 45 個 service）
- [ ] 重播、慢動作、全螢幕圖卡都是 no-play
- [ ] 沒有不到 0.3 秒的零碎片段
- [ ] service 的長度大多在 1.2～3 秒之間；短於 0.8 秒或長於 3.5 秒的要再確認
- [ ] 已經 `Ctrl+S`，畫面右上角顯示「已儲存」
- [ ] 備份 `db/annotations.db`（連同 `-wal`、`-shm` 檔一起複製）

### 需要標多少

| 目標 | 建議量 |
|---|---|
| 能用 | 1 部影片完整標註（約 20～45 個回合），另外 1 部當驗證 |
| 穩定 | 3～5 部同場地、同機位的影片 |

> **驗證集一定要用另一部影片**。如果同一個回合切出來的片段同時出現在訓練集和驗證集，準確率會虛高。
